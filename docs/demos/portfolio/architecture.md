# Autonomous demo portfolio integration

The integrated portfolio contains exactly App Modernization, Feature Delivery,
and Security and Dependency Remediation in Foundation order. The integration
validates each complete profile, journey, capability shard, runtime-binding
set, activation profile, projection mapping, Phase Contract, artifact asset,
agent, skill, workflow source, generated lock, and Foundation reservation
before dispatch.

Authority remains ordered and non-interchangeable:

1. lifecycle graph;
2. Work Accord and Phase Contracts;
3. policy compiler and Capability Registry;
4. Control Kernel;
5. trusted adapter;
6. Single Writer; and
7. model output.

The simulator and validators observe this order; they do not create a second
transition authority. Models never select a demo, repository, work item,
Project, stage, route, capability, workflow, target, command, credential,
retry, effect, approval, or merge. Project fields remain projections.

Runtime selection starts from the trusted catalog/profile/stage tuple. It
issues an opaque binding handle only after the complete registration pair is
validated. The execution bridge accepts demo execution only through that
handle and still requires the actual applied Kernel result, exact signed
authorization, target-free logical slots, fixed commands, threat evidence,
and the downstream Single Writer. Each implementation workflow passes its
fixed demo/stage tuple to both pre-activation and the post-agent bridge.

Exact-head review input is a signed bounded bundle containing the complete
pack command/check catalog, exact-success evidence digests, draft pull-request
identity, and redacted path/patch digests. App Modernization carries six fixed
commands, Feature Delivery carries four, and Security and Dependency
Remediation carries regression, lock, threat, DLP, scanner, unchanged-alert,
and COMMENT-only evidence. Head movement invalidates the bundle.

The bundle issuer derives repository, Project, pull-request, contract, and
complete diff identities from two byte-identical fresh trusted-reader
observations and requires the exact registered repository-binding digest;
the opaque registration accepts target identities only from fresh signed
trusted-adapter evidence bound to the exact profile/repository/Project
digests. Its expiry is retained and rechecked when the registration and review
bundle are consumed, and the bundle cannot outlive it. Callers cannot supply
those signed fields. Non-Git verification
commands are catalogued but fail closed in the privileged bridge process. A
sandbox deployment must provide a separately isolated, credentialless, and
network-denied runner before it can return authenticated command evidence.

Create slots may materialize missing parent directories only inside the
canonical authorized sandbox path after existing ancestors pass symlink/type
checks. The completed path is rechecked before staging.

Protected-path exceptions are closed to the exact App Modernization
implementation and Security Remediation patch capabilities and their reviewed
slot paths. A Work Accord containing zero or multiple exception capabilities
receives no exception. Security fixed checks are registered as trusted-evidence
commands; they cannot execute as shell processes.
