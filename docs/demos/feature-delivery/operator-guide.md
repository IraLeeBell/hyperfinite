# Feature Delivery operator guide

## Posture

The pack is disabled by default and hermetic-first. It declares no live Project, App, credential, billing, ruleset, deployment, publication, approval, or merge operation. A human administrator must separately configure any future live prerequisites; this pack does not perform or authorize that work.

## Walkthrough

1. Validate the content-addressed profile, exact nine-stage journey, capability/runtime-binding pair, activation profile, projection mapping, Phase Contracts, artifact templates, and synthetic Work Accord with the repository validation commands.
2. Inspect `trusted-binding.json`. Conventional code fixes the repository and exact base SHA. The issue repository hint, model text, and paths observed during discovery are evidence only.
3. Follow `examples/demos/feature-delivery/artifact-chain.json`. Stable acceptance IDs flow from the feature brief through discovery, design, the deterministic plan DAG, target-free patch, fixed tests, verification report, and human-review package.
4. Confirm Build contains only approved logical slots. Trusted code maps those slots to exact paths, validates the isolated diff, runs the generated TypeScript acceptance test directly plus every fixed regression/integrity command, and may create only a draft pull request.
5. Confirm Test and verification binds the exact current head and emits `COMMENT` only. Any head movement discards the report; repair, replan, or revision creates successor evidence and repeats every fixed command.
6. Stop the hands-off run at Human review. Only a separate eligible independent human invocation with current authorization and an authenticated merge observation can advance through `review.accept` to Completed.

Pause and block preserve the cursor. Cancel is terminal. Clarification uses a same-state receipt. Repair, replan, revision, retry, partial-effect reconciliation, lost-ack reconciliation, and reauthorization use the exact Kernel routes and never infer authority from Project state.
