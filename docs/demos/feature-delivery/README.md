# Feature Delivery demo pack

## Status

The Feature Delivery pack is disabled by default and hermetic first. It includes
closed contracts, synthetic evidence, five exclusive stage agents and skills,
compiled Agentic Workflow sources, deterministic test coverage, and a complete
receipt-backed simulation. It does not create a live Project, install an App,
use credentials, enable paid inference, mutate GitHub, approve, merge, deploy,
or publish.

## Journey and authority

The exact journey is:

1. Intake
2. Requirements clarification
3. Codebase discovery
4. Solution design
5. Implementation plan
6. Build
7. Test and verification
8. Human review
9. Completed

Requirements clarification, codebase discovery, solution design, build, and
test and verification have globally exclusive model agents. Intake is
deterministic, implementation planning is non-model planning, Human Review is
human-only, and Completed is terminal.

Displayed stages form a signed-receipt overlay on the unchanged lifecycle.
Same-core progress requires a signed stage receipt without Kernel movement.
Cross-core progress requires the exact applied Kernel route and receipt.
Project fields are projections and cannot authorize advancement.

## Traceability and delivery

Stable acceptance-criterion IDs flow through the feature brief, codebase impact
analysis, solution design, deterministic implementation-plan DAG, target-free
patch, fixed verification evidence, and human-review package.

Codebase discovery is bound to the trusted repository and exact base SHA.
Observed paths and issue text remain evidence only. Build output contains
logical slots rather than paths; trusted code maps those slots to exact
allowlisted paths, validates the complete isolated diff, and permits only a
draft pull request.

Test and verification binds every fixed command and the exact current PR head.
Automated review may emit only `COMMENT`; head movement invalidates the evidence.
The hands-off path stops at Human Review. A separate synthetic-human
continuation demonstrates Completed from independent current-head approval and
later merge observation without giving automation either authority.

## Integrated runtime boundary

Portfolio integration loads the exact Feature Delivery registration,
authenticates its fixed command/evidence catalog, and enforces the final
current-head condition at the `COMMENT` boundary. Non-Git commands still require
the separately deployed credentialless, network-denied runner. Live activation
remains blocked on the human-admin prerequisites in
[Portfolio activation and readiness](../portfolio/activation-and-readiness.md).
