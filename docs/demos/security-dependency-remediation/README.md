# Security and Dependency Remediation journey

## Status

The pack is a disabled-by-default, hermetic-first demonstration. It uses only
original fictional evidence and repository fixtures. No live repository,
Project, App, credential, alert, review, deployment, publication, or production
system is configured or mutated.

## Journey and authority

The displayed order is Intake, Triage, Reproduction and impact analysis,
Remediation design, Patch planning, Patch implementation, Security
verification, Human review, and Completed. These stages are a signed-receipt
overlay on the unchanged lifecycle. Same-core-state movement requires a signed
stage receipt without Kernel movement; cross-state movement requires the exact
applied Kernel route and receipt.

Only Triage, Reproduction and impact analysis, Remediation design, Patch
implementation, and Security verification have exclusive runtime agents.
Intake is deterministic, Patch planning is non-model planning, Human review is
human-only, and Completed is terminal.

The authority order remains lifecycle graph, Work Accord and Phase Contracts,
policy compiler and Capability Registry, Control Kernel, trusted adapter,
Single Writer, then model output. GitHub Projects are projections only.

## Synthetic subject

The fictional local dependency `mist-lru` `0.4.0` joins namespace and cache key
with an unescaped colon. The safe fixture demonstrates that `(\"a:b\", \"c\")`
and `(\"a\", \"b:c\")` collide. The proposed `0.4.1` patch length-prefixes both
inputs. This is a data-integrity example, not a production exploit.

Trusted configuration fixes the synthetic repository, advisory, dependency and
versions, base SHA, four logical target slots, six check IDs, and finite budget.
User text cannot replace any of those values.

## Delivery and completion

Patch implementation emits only `TargetFreePatch@1.0.0`. Trusted delivery maps
logical slots to exact paths, validates the complete diff, and may create only
an open draft pull request. Security verification binds exact-current-head
regression, dependency/lock consistency, exact-success threat and DLP results,
and signed current synthetic scanner evidence. Automated review can emit only
`COMMENT`.

The hermetic scenario reaches Human Review with closed, zero-valued
fixture-declared external-call assertions. A separate synthetic-human scenario
demonstrates the Human Review to Completed transition; it does not grant
automation approval or merge authority. Fixture declarations are not runtime
telemetry or proof of OS-level isolation.
