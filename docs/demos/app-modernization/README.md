# App Modernization demo pack

## Status

The pack is disabled by default and hermetic first. It defines reviewable
contracts, synthetic evidence, exclusive stage agents, and compiled Agentic
Workflow sources. It does not activate paid inference, install an App, create a
Project, clone a target, use credentials, mutate live GitHub, approve, merge,
deploy, publish, or migrate production.

## Authority and journey

Authority remains lifecycle graph, Work Accord and Phase Contracts, policy
compiler and Capability Registry, Control Kernel, trusted adapter, Single
Writer, then model output. GitHub Project fields are projections only.

The nine-artifact chain begins with bounded intake, then records inventory,
assessment, risk/compatibility, target architecture, migration plan,
implementation evidence, verification, and the human-review package.

The exact journey is Intake; Repository discovery; Current-state inventory;
Modernization assessment; Target architecture; Migration plan; Implementation;
Verification; Human review; Completed. Only inventory, assessment, target
architecture, implementation, and verification have globally exclusive model
agents. Same-core advances require signed stage receipts. Cross-core advances
require the exact applied Kernel result.

Repository discovery accepts only the reviewed binding for numeric/node/full
repository identity, `refs/heads/main`, and one exact SHA. Hints and observed
paths remain untrusted evidence.

Implementation receives logical slots, not paths. Trusted code maps the slots,
subtracts protected surfaces, validates the complete diff, runs fixed offline
commands, and permits draft-pull-request delivery only. Verification binds the
current PR head and emits only `COMMENT`; any head movement invalidates it.

## Integrated runtime boundary

Portfolio integration now loads the exact trusted demo tuple during
pre-activation, validates App Modernization execution through an opaque
registered binding, authenticates the six-command verification catalog, and
materializes an exact-current-head review bundle. The privileged bridge remains
Git-only; non-Git verification requires the separately deployed credentialless,
network-denied runner.

The checked-in activation remains disabled. No repository evidence provisions a
Project, deploys the required trust services, authorizes paid inference, or
permits a live write. Follow the
[portfolio activation checklist](../portfolio/activation-and-readiness.md) for
the human-admin boundary.
